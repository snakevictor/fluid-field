# Existing mods, plugins and tools for Fluid Field

Oct 14, 2026 · research note (web survey, nothing installed or downloaded)

The question was which existing mods, SKSE plugins, frameworks or tools Fluid Field should use for development, testing or the feature itself. The guiding principle is D8: extend what Skyrim and Community Shaders (CS) already do. The target runtime is Steam AE 1.7.104 with SKSE 2.3.1. SE 1.5.97, AE 1.6.1170 and VR are secondary.

How to read the verdicts:

-   **Use now:** install, or act on, today.
-   **Use later:** worth it in a named phase.
-   **Study only:** read the code or behaviour; take no dependency.
-   **Skip:** not worth the time.
-   **Test target:** a mod to put in the compatibility matrix, not to build against.

Facts I could not confirm from a primary source are marked UNVERIFIED. Nexus blocks automated fetching (HTTP 403), so Nexus facts come from search snippets, Step wiki pages and mod.pub mirrors. GitHub repos were read directly.

## Use now

1. **Keep the debug stack as it is: SKSE 2.3.1, Address Library v13 (AIO, 1.7.104), Crash Logger 1.25.0 and devbench 1.28.0.** Nothing else is needed to develop Fluid Field.
    - Make sure Address Library is v13 or newer, the build that contains `versionlib-1-7-104-0.bin`. The mod.pub mirror lists "All in one … 1.7.104", uploaded 27 Aug 2026.
    - The CS build already deploys its PDB (`CMakeLists.txt:718, 911`), so Crash Logger stacks show Fluid Field symbols.
2. **Extend devbench rather than adding more test mods.**
    - CS already registers tools through `src/Features/RemoteControl/DevBenchBridge.cpp`.
    - Add Fluid Field tools there: puff of wind, layer overlay toggle, solver stats, and later a readback probe. Today the phase 1 checks cannot reach these because they are menu-only (`reports/phase1-grid-core-checks.md`).
    - Use devbench `record` / `replay` and `scenario` for the fixed test routes, the one-hour soak and the horse gallop across a cell border.
    - This replaces the "test-save / alternate start" category: start from `coc Riverwood` and saves made by devbench.
3. **Read now: Splashes of Skyrim PR #5** ([powerof3/Splashes-of-Skyrim#5](https://github.com/powerof3/Splashes-of-Skyrim/pull/5/files)).
    - It fixed a crash with CS Unified Water by null-checking and locking while iterating `TESWaterSystem::waterObjects` and `multiBounds`.
    - Fluid Field's R1 stage b (D7) iterates the same list. Copy the pattern; the code is GPL-3.0. Its README says MIT, so check the licence before copying verbatim.
4. **Look now at a likely competitor: SurfaceTides – True Water Simulation** ([Nexus SSE 191955](https://www.nexusmods.com/skyrimspecialedition/mods/191955)).
    - It is an SKSE "true water simulation" for Skyrim's waterways. Search snippets say it is AI-coded and CPU-bound.
    - What it simulates, whether its source is public, and how it behaves with Unified Water are all UNVERIFIED. The page returns 403 to tools.
    - The user should read the page by hand. Fluid Field should at least detect its DLL and warn.
5. **Use CommonLibSSE-NG directly for every input and for Havok forces.** No third-party runtime dependency is needed for Phases 2 to 6 (table 2 and table 6).
    - The repo's CommonLib (`extern/CommonLibSSE-NG`, 6.7.1, 26 Aug 2026) already parses the format-5 Address Library used on 1.7.99 and newer (`src/REL/IDDB.cpp:49, 107, 220`).
    - Many third-party plugins broke on 1.7.104 for lack of exactly this. Every extra dependency is one more thing that must be re-released after each Bethesda patch.
6. **Optional tools that need no install in the game:**
    - xEdit (SSEEdit), to inspect WATR, MATT (buoyancy `BNAM`) and fire or smoke forms.
    - NifSkope, to see how fire replacers build their particle systems.

## 2. Physics and Havok (Phase 2 inputs, Phase 6 buoyancy, R7)

**Main finding:** no mod offers a stable public API for pushing loose clutter on SE or AE.

-   The force-related APIs that exist are HIGGS and Planck (VR) and Precision (actor hit impulses only).
-   For R7, use CommonLib directly. The local headers declare:
    -   `RE::hkpRigidBody::ApplyLinearImpulse` and `SetLinearVelocity` (`include/RE/H/hkpRigidBody.h`).
    -   `RE::bhkRigidBody::SetLinearImpulse`, `SetAngularImpulse`, `SetLinearVelocity` and `SetAngularVelocity`.
    -   The `bhkWorld::worldLock` read-write lock, taken with `BSWriteLockGuard`.
-   Impulses are no-ops on keyframed and fixed motions (`hkpKeyframedRigidMotion.h:27`, `hkpFixedRigidMotion.h:16`), so filter on motion type first.
-   How to wake a sleeping body is UNVERIFIED.
-   **Vanilla already floats objects.** MATT records carry a buoyancy value `BNAM` ([UESP MATT](https://en.uesp.net/wiki/Tes5Mod:Mod_File_Format/MATT)). Phase 6 should add wave lift, drag and current on top of vanilla buoyancy, or read `BNAM`, rather than duplicate it. This belongs in R7.

## 4. Weather, wind, fog, shouts and magic

**Wind is already in the engine and in CS.**

-   `RE::Sky::windSpeed` and `windAngle`, plus `TESWeather` `windSpeed`, `windDirection` and `windDirectionRange`, are in CommonLib.
-   CS already passes `WindVector` and `WindTimer` (`src/ShaderCache.cpp:900`) and particle `Wind` (`package/Shaders/Particle.hlsl:60, 155`), and has `WIND_RAW_TO_NORMALIZED` in `Common/Game.hlsli`.
-   Phase 1 should seed the far-field wind from these, not from a weather mod.
-   Weather mods (Cathedral, Obsidian, Azurite, NAT) are ESP data only, so reading `TESWeather` covers them automatically.

## 5. Fire, smoke and VFX (Phase 5, R5)

Replacers overwrite vanilla file paths, so detecting them by path finds the object while the content differs. Some packs also swap base objects with Base Object Swapper, which defeats detection by form. The more robust approach, at attach time (and part of R5):

-   Walk the reference's 3D for `NiParticleSystem` / `BSEffectShaderProperty` with fire or smoke textures under `textures/effects/`.
-   Combine that with the base form type (MSTT, ACTI, LIGH).
-   Check whether a `BSWindModifier` is already attached.

No existing simulated or volumetric fire or smoke mod for Skyrim was found. This negative result is UNVERIFIED.

## Ranked summary

1. CommonLib directly for all inputs and Havok forces; it already handles 1.7.104.
2. devbench plus `DevBenchBridge` Fluid Field tools, and record and replay for the test routes.
3. Crash Logger with PDB, Address Library v13 and SKSE 2.3.1 (installed or verify).
4. Code to study now, all GPL or MIT:
    - Splashes of Skyrim PR #5 (safe `waterObjects` iteration).
    - Wade In Water Redone (submersion).
    - Particle Wind (engine wind hook).
    - Papyrus Extender (projectile and magic hooks).
    - HIGGS (pre-physics-step forces, R7).
5. SurfaceTides: read its page and decide whether it changes Fluid Field's positioning.
6. Later: Precision (soft dependency), KID (buoyancy keywords), Light Placer configs (fire classification), Seasons of Skyrim (ice), Display Tweaks and the CS frame limiter (Phase 6 FPS tests).
7. Test targets: Water for ENB, Realistic Water Two, Simplicity of Sea, Embers XD, Inferno, Particle Patch, NAT.CS, True Storms, fog-mesh mods, Thunderchild, FSMP.

## Open questions

1. **SurfaceTides:** what does it simulate, is its source public, and does it conflict with Unified Water or Fluid Field? It needs a manual read of the Nexus page and possibly an in-game test on a separate profile.
2. **Which third-party plugins actually load on 1.7.104?** It is only confirmed for Crash Logger (1.7.99 per its notes, running on 1.7.104 here), Papyrus Extender 6.5.2 (secondary source) and the CS dev build.
    - Each "Use later" dependency must be re-checked when its phase starts.
    - A third-party blog reports that CS 1.8.4 itself failed on 1.7.104 ([rpgmodding](https://rpgmodding.blogspot.com/2026/09/skyrim-171040-skse-231-address-library.html)). Our dev build works, since its CommonLib parses format 5.
3. **Vanilla MATT `BNAM` buoyancy:** how does the engine apply it, and at which point in the Havok step? This is the starting point for R7.
4. **Waking a sleeping `hkpRigidBody`:** no CommonLib helper was found (R7).
5. **Particle Wind:** should Fluid Field take over its role near the player, or turn its own particle wind off when it is present? Decide in Phase 5 and R5.
6. **Splashes of Skyrim:** what is its DLL name, and how should Fluid Field share splash duty with it (damp our impulses, or feed it)?
7. **Licences:** Splashes of Skyrim and Seasons of Skyrim have conflicting GPL/MIT labels. Ask powerofthree before copying anything verbatim.
